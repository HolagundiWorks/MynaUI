### 4 · `SuiteAccentText` in dark mode — SC 1.4.3 FAIL (text contrast)

`SuiteAccentText = #A83A00` is defined in `SuiteAccent.Orange.xaml` and is designed for light surfaces. `SuiteColors.Dark.xaml` did not override it, so dark-mode builds inherit the light value unchanged.

| Background | Old (inherited #A83A00) | New (#FF7040) |
|---|---|---|
| BG `#1B1F28` | 2.57:1 ❌ | **6.00:1 ✓** |
| Surface `#242A36` | 2.24:1 ❌ | **5.24:1 ✓** |
| Sidebar `#151922` | 2.74:1 ❌ | **6.40:1 ✓** |

**Used for:** accent-coloured text (links, active labels) on dark backgrounds via `BrandAccentAccessibleBrush`.  
**Fix:** `SuiteColors.Dark.xaml` — added `<Color x:Key="SuiteAccentText">#FF7040</Color>` override.  
**Hue note:** `#FF7040` is a warm orange-red consistent with the `#FF5B04` brand accent; it passes all three dark backgrounds with significant headroom (≥5.2:1).

## Failures Requiring Design Decisions (Not Auto-Fixed)

### 5 · `SuiteEdge` (card borders) — SC 1.4.11 FAIL — architectural issue

`SuiteEdge = #D8DEE8` provides card and panel borders. The card surface (`#FFFFFF`) is only 1.21:1 against the page background (`#E4EAF2`), so neither the border colour nor the surface elevation provides 3:1 non-text contrast as required for UI component boundaries under 1.4.11.

| Pair | Ratio |
|---|---|
| `SuiteEdge` on BG `#E4EAF2` | 1.12:1 ❌ |
| `SuiteSurface` on BG | 1.21:1 ❌ |

**Resolution options (design decision needed):**  
a) Darken `SuiteEdge` significantly (toward `#788090` = new EdgeStrong level) — changes the visual density of all card borders throughout the suite.  
b) Remove reliance on border contrast for card boundaries; use shadow/elevation as a visual separator only, and ensure card content itself meets contrast. Per WCAG, if shape alone defines a component boundary, the shape must meet 3:1. If multiple cues define it (shadow + border + content), the analysis depends on which cues are present for users who cannot perceive others.  
c) Accept as a known gap with a compensating note in the design system docs (shadow/depth communicates containment; borders are decorative at this density).

**Recommendation:** Option (b) is most defensible if shadow is always present. If targeting strict 1.4.11 compliance for all users including those with high-contrast overrides disabled, option (a) is required.

### 6 · `SuiteOnAccent` on `SuiteAccentPressed` — **FIXED**

`SuiteAccentPressed` changed from `#E64E00` to `#FF4E00`. The pressed state shifts hue toward red-orange (which reads naturally as a press feedback) while restoring the R channel to 0xFF so luminance stays in the passing range.

| Pair | Old ratio | New ratio |
|---|---|---|
| `#16232B` on AccentPressed | 4.17:1 ❌ | **4.84:1 ✓** |
| `#16232B` on AccentHover `#F25400` | 4.62:1 ✓ | 4.62:1 ✓ |
| `#16232B` on AccentDefault `#FF5B04` | 5.16:1 ✓ | 5.16:1 ✓ |

**Fix:** `SuiteAccent.Orange.xaml` — `SuiteAccentPressed` changed from `#E64E00` to `#FF4E00`.  
**Note:** The hue shift (R returns to 0xFF, G drops from 78 to 78 via 0x4E=78 — same G!) Wait — 0x4E = 78, same as old 0x4E in #E64E**00**. But 0xFF vs 0xE6 for R means the new pressed is brighter-but-more-red-shifted. Combined with a button scale-down transform, pressed state remains visually distinct from hover.

## Addendum 2026-11-02: after the Light Conditions palette

The numbers above were taken on the earlier orange palette (`#FF5B04`). The palette is now Ember, Midnight, Grove and Dusk (`docs/BRANDING.md` in O-Studio), so the findings were re-run:

| Finding | Result | Fix |
|---|---|---|
| Light accents as text on the light surfaces | Pass: Ember 4.6 on BG and 5.6 on white; Midnight 10.2 / 12.4; Grove 6.2 / 7.6; Dusk 7.5 / 9.0 | none needed |
| White on each accent fill | Pass: Ember 5.6, Dusk 9.0, Grove 7.6, Midnight 12.4 | none needed |
| Accent as fill or text on the dark surfaces | **Fail**: Midnight 1.2 to 1.4, Dusk 1.6 to 1.9, Grove 1.9 to 2.3, Ember 2.6 to 3.1; and every app inherited Ember's dark accent text | `SuiteAccent.<App>.Dark.xaml` (generated): a lighter tint of each app's colour with dark text on a fill, all at least 4.8 : 1 for text and 3 : 1 or more against the dark surfaces |
| Ink | Brand guide says Midnight; the library had slate `#1A2332` | `SuiteInk` = `#102C80` (12.4 on white, 10.2 on BG) |
| Ink soft | `#546B88` was 4.52 on BG, the edge of AA | `SuiteInkSoft` = Midnight soft `#3E56A0` (5.7 on BG, 6.9 on white) |
| Plain text and some control foregrounds | Took the Windows black or white, not the suite ink | `DefaultTextForegroundThemeBrush` and the control foregrounds are set in the light and dark theme templates |
| `SuiteThemeSwitch` checked state | Took the user's Windows accent (cyan) | Uses the app's `SuiteAccent` |
| Ask bar pill | Corner radius 28 on a 40 high bar (more than half the height) distorted the ends | Radius = height / 2 |

Still a design decision: card borders (item 5 above) are decorative against the page background.
